# Прачечная-бот ВКонтакте (VK-порт tg-бота)

Полный порт Telegram-бота на VK с помощью библиотеки [vkbottle](https://vkbottle.readthedocs.io/).
Бот работает с той же базой данных Supabase, что и Telegram-версия — оба бота могут
работать одновременно.

## 1. Перед первым запуском — миграция БД (обязательно)

Оба бота (tg и vk) используют одну и ту же таблицу `residents`. У tg-бота там уже есть
колонка `tg_id`, а под VK нужна отдельная `vk_id` (чтобы Telegram- и VK-аккаунты не
конфликтовали между собой — это разные числа).

Выполните **один раз** в SQL Editor вашего проекта Supabase:

```sql
ALTER TABLE residents ADD COLUMN IF NOT EXISTS vk_id BIGINT;
CREATE INDEX IF NOT EXISTS idx_residents_vk_id ON residents (vk_id);
```

(тот же скрипт лежит в `migrations/001_add_vk_id.sql`)

Без этого шага бот будет падать с ошибкой SQLAlchemy при первом же обращении к БД.

## 2. Настройки сообщества ВКонтакте

В настройках вашего сообщества (Управление → Сообщения):
- Включите **"Сообщения сообщества"**
- Включите **Long Poll API** (Настройки → Работа с API → Long Poll API → Включено,
  версия API можно оставить по умолчанию)
- В разделе **"Возможности ботов"** включите обработку событий (в т.ч. кнопки с
  callback — иначе inline-кнопки бота просто не будут отвечать на нажатия)
- По желанию — настройте кнопку **"Начать"** (тогда при первом заходе будет
  автоматически приходить payload `{"command":"start"}`; если не настраивать,
  бот всё равно сработает на текст "начать"/"start")

## 3. Установка и запуск

```bash
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

`.env` уже настроен (в нём уже есть `VK_TOKEN`, `GROUP_ID` и данные подключения к
Supabase — те же, что и у tg-бота).

## ⚠️ Важно: ротация секретов

В присланных архивах в файлах `.env` были "живые" токен Telegram-бота, токен
VK-сообщества и пароль от БД Supabase в открытом виде. Я не публикую и не вывожу
их здесь, но раз эти файлы уже путешествовали в переписке/архивах — рекомендую
после того, как всё заработает, **сменить токены и пароль от БД** (в настройках
сообщества VK, у @BotFather для Telegram, в Supabase → Database → Reset password),
и обновить `.env` новыми значениями.

## Фиксы после первого реального запуска

При первом прогоне на вашей боевой БД вскрылись два несоответствия схемы
(их не было видно без доступа к реальной Supabase):

- **`machines.status`** в реальной таблице — `smallint` (не `varchar`, как
  предполагала модель). Значение `1` = машина активна. Модель и все запросы
  поправлены на сравнение с числом (`MACHINE_STATUS_ACTIVE = 1` в
  `app/db/models/machine.py`).
- **Статус отменённой брони.** Несколько запросов в `laundry_repo.py`
  фильтровали `Booking.status != 'cancelled'` (английское слово), а по факту
  в БД отменённые записи хранятся как `'Отменено'`. Из-за этого отменённые
  брони продолжали бы считаться занимающими слот. Этот же баг есть и в
  исходном tg-боте — не я его внёс, но раз уже чинили здесь, стоит поправить
  и там тоже. Исправлено во всех местах на `!= 'Отменено'`.

## Чем VK-версия отличается от Telegram-версии

- **Календарь.** У Telegram нет ограничений на размер inline-клавиатуры, поэтому
  использовалась полноценная помесячная сетка (`aiogram_calendar`). У VK жёсткий
  лимит — максимум 5 кнопок в строке и 6 строк на inline-клавиатуру, из-за чего
  сетка 7×6 туда физически не помещается. Вместо неё сделан пролистываемый список
  ближайших дней (по 15 штук, с пагинацией вперёд/назад) — с теми же индикаторами
  загруженности 🟢/🟡/🔴/⚪. Учитывая, что бронь ограничена одной записью в неделю
  на тип машины, глубина в пару недель вперёд более чем достаточна.
- **`confirmation.py` отсутствовал в присланном архиве tg-бота** (был только
  скомпилированный `.pyc`), но его нетронутая копия нашлась в заготовке VK-бота
  — так что содержимое не пришлось восстанавливать вслепую.
- **HTML-теги** (`<b>...</b>`) из текстов локализации вырезаются перед отправкой —
  VK не поддерживает `parse_mode="HTML"`, как Telegram.
- **Уведомление об автоотмене брони.** В исходном `scheduler.py` этот момент был
  недописан (заглушка `...` с комментарием "скопируйте тело уведомления"). В VK-версии
  я его доделал: если бронь отменяется автоматически из-за неподтверждения, юзер
  получает сообщение с текстом из `booking_autocanceled` (такой ключ уже был в
  локализации, но нигде не использовался).
- **`back_to_sections`** обрабатывается один раз в `booking.py`, а не дублируется в
  каждом хендлере — в исходном tg-боте эти дубли в `records.py`/`cancel_record.py`
  всё равно были недостижимы (их всегда перехватывал первый зарегистрированный
  роутер), так что это не потеря функциональности, а просто чистка мёртвого кода.
- Список записей для отмены (`get_cancel_booking_keyboard`) ограничен 5 записями —
  это предел inline-клавиатуры VK (5 записей + кнопка "назад" = 6 строк).

## Структура проекта

```
app/
  config.py            — переменные окружения
  laundry_repo.py       — вся работа с БД (SQLAlchemy, без изменений в бизнес-логике)
  db/                   — модели SQLAlchemy (Resident с vk_id, Machine, Booking, ...)
  locales/               — тексты RU/ENG/CN (без изменений)
  bot/
    loader.py            — единый экземпляр Bot/API/StateDispenser
    states.py             — состояния FSM (BaseStateGroup)
    keyboards.py           — все клавиатуры (Callback-кнопки)
    utils/
      fsm.py                — аналог FSMContext (get/update/clear state)
      calendar_utils.py       — новый календарь-список дат
      translate.py             — выбор текстов по языку
      text.py                   — вырезание HTML из текстов
      broadcaster.py             — рассылка "слот освободился"
      scheduler.py                — напоминания о подтверждении + автоотмена
    handlers/
      auth.py — booking.py — cancel_record.py — confirmation.py — records.py — report.py
main.py                — точка входа
migrations/001_add_vk_id.sql
```

## Что не проверено "живьём"

Я проверил, что весь проект целиком импортируется без ошибок и что все клавиатуры
укладываются в лимиты VK (автоматические тесты), но у меня нет доступа к вашему VK
API и к вашей базе Supabase, поэтому реальный прогон бота (регистрация по ФИО/зачётке,
запись на стирку, отмена, напоминания) стоит один раз пройти руками после запуска.
